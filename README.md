# card-service

«Мозг» медицинской карты — П1–П8 из `../CARD_ARCHITECTURE_PLAN_2026-09-13.md`. Не заменяет n8n сразу и целиком — растёт рядом, поверх Postgres (схема `card` в контейнере `pg`, рядом с существующей `health`), пока каждый кусок не докажет паритет со старой системой и не примет эстафету.

## Статус

**Phase 0 — скелет.** Есть только `/health`. Никакой бизнес-логики, никакого подключения к Postgres, никакого `/ingest` ещё нет — по плану они появляются следующим шагом Phase 0/1.

## Локальный запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8080
```

Сервис слушает **только на 127.0.0.1** и в проде, и локально — публично он не торчит никогда; единственная публичная точка всей системы — n8n-webhook за TLS.

## Тесты — обязательны перед любым деплоем

Это не пожелание, это условие всей архитектуры П1–П8: «деплой без прогона корпуса запрещён» (инвариант из П5/П7-спецификации). Пока корпусов нет — есть обычные unit/integration тесты, и правило то же:

```bash
source .venv/bin/activate
pytest -v
```

Красный тест = не деплоим. Это тот же принцип, что уже применяется к n8n-воркфлоу (parser-gate + syntax-check перед публикацией) — только здесь инструмент pytest, а не самодельный скрипт.

## Структура

```
app/            # FastAPI-приложение — вся логика
tests/          # pytest — растёт вместе с app/, 1:1 где возможно
fixtures/       # golden-фикстуры (карта на конкретный момент, ожидаемые рендеры) — появятся с Phase 1+
```

## Почему отдельный git-репозиторий

Основной проект (`longevity-project/`) исторически не был git-репозиторием — патчи применялись точечными скриптами прямо к живой n8n/Postgres. card-service — новый код на новом языке, и с него дисциплина начинается сразу: коммит на каждый осмысленный шаг, никаких прямых правок в обход git.
