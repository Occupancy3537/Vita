# UI/UX Roadmap — ВИТА (аудит Qwen)

**Дата аудита:** 2026-09-29
**Оценка:** 8/10 — сильный визуальный уровень «Oura», собственная задокументированная ДС, но есть критические gaps в доступности и состояниях ошибок.
**Объекты аудита:** `app/static/vita.html` (главный PWA-экран), `app/static/vita_login.html`, `app/static/nutrition_widget.html`, манифест PWA.

Ключевые проблемы, которые решает роадмап:

| # | Проблема | Уровень |
|---|----------|---------|
| 1 | Примитивный error-state главного экрана: текст ошибки в шапке без кнопки retry, нет skeleton-загрузки | Critical |
| 2 | Переключатель темы недоступен на мобильном; тёмная тема конфликтует с фото-hero | Critical |
| 3 | Модальные шторки без focus trap / inert фона | Critical |
| 4 | Таг-зоны < 44px, мелкий muted-текст на границе контраста AA, битая ARIA-семантика табов, индекс дня читается только цветом (colorblind) | Medium |
| 5 | Мёртвый код: soon-screen, sw-under, выключенный swipe-трек | Medium |
| 6 | Фрагментация дизайн-системы: 3 файла с разными палитрами/шрифтами; монолит vita.html ~2000 строк с двойным объявлением токенов | Medium |

---

## Приоритет 1 — Состояния загрузки и ошибок (критично, ~1–2 дня)

- [ ] Заменить текстовую ошибку в шапке на полноценный **error-state компонент**: иконка, объяснение человеческим языком, кнопка «Повторить», ссылка «Написать поддержку».
- [ ] Добавить **skeleton-экраны** для карточек метрик, графика сна и ленты питания вместо пустых блоков/спиннера.
- [ ] Обработать offline-состояние: баннер «Нет соединения — показаны данные за …» + queue-логика для исходящих действий.
- [ ] Таймаут fetch (10 c) с auto-retry ×1 перед показом ошибки.

**Done when:** при обрыве сети / 500 от бэкенда пользователь видит понятное состояние с действием, а не мёртвый экран.

## Приоритет 2 — Доступность модальных шторок (критично, ~1 день)

- [ ] Focus trap внутри открытой шторки (Tab циклует по элементам шторки).
- [ ] `inert` (или `aria-hidden="true"` + tabindex=-1) на фоновом контенте при открытой шторке.
- [ ] `role="dialog"` + `aria-modal="true"` + `aria-labelledby` на заголовке шторки.
- [ ] Возврат фокуса на триггер при закрытии; Esc закрывает шторку.
- [ ] Блокировка прокрутки body без «прыжка» layout (компенсация scrollbar-width).

**Done when:** шторка «Питание» полностью управляема с клавиатуры/screen reader.

## Приоритет 3 — Тема и hero-конфликт (критично, ~1–2 дня)

- [ ] Сделать переключатель темы доступным на мобильном (место в header или long-press на аватар; не прятать в hover-only).
- [ ] Разрешить конфликт тёмной темы с фото-hero: затемняющий градиент-оверлей поверх фото в dark mode + адаптивная подложка карточек над фото.
- [ ] Сохранять выбор темы в localStorage + уважать `prefers-color-scheme` при первом визите.
- [ ] Проверить контраст всех пар token-фонов/текста в обеих темах (скрипт-чекер или плагин Stark).

**Done when:** обе темы консистентны, переключаемы с телефона, контраст ≥ 4.5:1 для body-текста.

## Приоритет 4 — Мелкая моторика, цвет, семантика (средне, ~2–3 дня)

- [ ] Все таг-зоны интерактивных элементов ≥ 44×44 px (иконки в тулбаре, чипсы фильтров, крестики закрытия).
- [ ] Поднять минимальный размер muted-текста до 12–13 px и/или осветлить/затемнить muted-токен до прохода AA.
- [ ] Починить ARIA табов: `role="tablist" / tab / tabpanel`, `aria-selected`, управление стрелками ←/→.
- [ ] Индекс дня: добавить не-цветовой канал восприятия — цифру рядом с кольцом, паттерн/иконку статуса, текстовую подпись («Хороший день»).
- [ ] Графики: `aria-label`/таблица-фолбэк для screen reader, паттерны штриховки как дубль цветовых серий.

**Done when:** аудит axe/Lighthouse a11y ≥ 95; навигация с клавиатуры без ловушек.

## Приоритет 5 — Санация мёртвого кода (средне, ~0.5 дня)

- [ ] Удалить `soon-screen` (или реализовать как честный coming-soon state, если экран планируется).
- [ ] Удалить неиспользуемый класс `sw-under` и выключенный swipe-трек либо вернуть swipe-навигацию между экранами.
- [ ] Прогнать coverage CSS (например, PurgeCSS в dry-run) — удалить мёртвые правила из vita.html.
- [ ] Закоммитить решение в README ДС: что удалено и почему, чтобы не воскресало.

**Done when:** нет правил/JS-блоков, не участвующих в рендере; −N КБ веса страницы (замерить до/после).

## Приоритет 6 — Консолидация дизайн-системы (средне, ~3–5 дней)

- [ ] Вынести общие токены (палитра, типографика, отступы, радиусы, тени, motion) в один файл `app/static/vita_public/tokens.css`.
- [ ] Единый источник шрифтов и иконок для vita.html / vita_login.html / nutrition_widget.html — устранить расхождение палитр login/widget vs app.
- [ ] Разбить монолит vita.html (~2000 строк): `base.css`, `components/*.css`, модули JS по экранам (dashboard / sleep / nutrition / profile).
- [ ] Стилевой lint (stylelint + конфиг токенов) в CI: запрет хардкод-цветов вне tokens.css.
- [ ] Обновить документацию ДС (ДС v2 → v2.1): страница токенов, правила темизации, состояния компонентов.

**Done when:** три интерфейса визуально собраны из одних токенов; изменение палитры = правка одного файла.

## Рекомендуемый порядок и оценка

| Неделя | Задачи | Итог |
|--------|--------|------|
| W1 | P1 + P2 | Надёжные состояния + доступные модалки |
| W2 | P3 + P5 | Темы ок, вес страницы снижен |
| W3–W4 | P4 + P6 | A11y ≥ 95, единая ДС, CI-lint |

**Метрики успеха:** Lighthouse A11y ≥ 95, Best Practices ≥ 95; TTI главной ≤ 2.5 c на 4G; 0 console errors при offline; покрытие скриншот-тестами обеих тем.
